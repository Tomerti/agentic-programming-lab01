# Iron Dome: Jerusalem Battery — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the browser game described in the spec: a seated, low-poly 3D control room in which the player intercepts rockets over Jerusalem, with a coin economy, lives, a shop, missions, a 10-round campaign plus Endless, day/night and synthesized audio.

**Architecture:** Pure game logic (`js/core`, `js/game`) with no DOM/Three/timers, driven by `session.update(dt)` and emitting events on a bus; presentation modules (`js/scene`, `js/ui`, `js/audio.js`) read session state and subscribe to events. `js/main.js` wires everything and runs the frame loop. Logic is unit-tested with `node --test`; visuals are checked with a headless-Chrome harness that captures console errors and screenshots.

**Tech Stack:** Vanilla ES modules, Three.js `0.170.0` via importmap from jsDelivr (`RoundedBoxGeometry` addon), Canvas 2D for monitor screens, Web Audio API, `localStorage`, Node 24 built-in test runner, Python `http.server` for local serving, Chrome headless for visual checks.

**Spec:** `docs/superpowers/specs/2026-10-14-iron-dome-design.md`

## Global Constraints

- Plain HTML, CSS and JavaScript only: no server, backend, database, API keys, build step, bundler or npm dependencies (`package.json` has no `dependencies`/`devDependencies`).
- Three.js pinned to exactly `three@0.170.0` through the importmap in `index.html`; addons from `https://cdn.jsdelivr.net/npm/three@0.170.0/examples/jsm/`.
- `js/core/*` and `js/game/*` never import Three, touch `document`/`window`, use timers or `Math.random`; RNG and storage are injected.
- Every module is an ES module; the page must work when served from a static HTTP origin (GitHub Pages root, `python -m http.server`).
- English UI; desktop first (≥1280 px, mouse + keyboard).
- All numbers come from the spec tables and live in `js/config.js`; no magic numbers in logic modules.
- Commit after every task with a message in imperative mood ending with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Verification commands, run from the repo root: `npm test` (= `node --test tests/`), `node scripts/check.mjs`, `node scripts/snap.mjs <url> ...` (see Task 1).

## Review Focus

1. Browser tab hidden or a long frame → a huge `dt` must not teleport rockets into the city: `main.js` clamps `dt` to 0.1 s and `session.update` clamps again (test in Task 9).
2. A click or hotkey for ENGAGE/ALERT while the phase is `title`, `summary`, `shop`, `paused`, `gameover` or `victory` must be ignored without spending coins or throwing (test in Task 9).
3. `localStorage` unavailable or throwing (private mode, blocked storage) must still start the game with defaults and never throw on save (test in Task 7).
4. Window resize or an unusual aspect ratio must keep the window-view in frame and the HUD readable: vertical FOV adapts to aspect and the renderer resizes (check in Task 10).
5. WebGL or the CDN failing must show a readable `#fatal` message instead of a blank page (check in Task 10).

### Task 3: Threats: creation, flight paths, detection

**Files:**
- Create: `js/game/threats.js`
- Test: `tests/threats.test.js`

**Interfaces:**
- Consumes: `WORLD`, `THREATS` from `js/config.js`; `rngRange`, `rngInt`, `rngPick` from `js/core/rng.js`.
- Produces:
  - `pickImpactPoint(zone, rng, world = WORLD) → {x, y: world.impactY, z}`: a uniform point inside the neighborhood circle for a neighborhood id, or inside a random open-area rectangle for `'open'`.
  - `pickSpawnPoint(type, impact, rng, world = WORLD, threats = THREATS) → {x, y, z}`: mortar → `distance ∈ [6,8]` from `impact` horizontally, on the side of `impact` away from x = 0 (`x` sign = sign of `impact.x`, or +1 when 0), `y = 5`; `low` types → `x = ±rng[14,16]`, `y ∈ lowSpawnY`, `z ∈ spawn.z`; others → `x = ±[14,16]`, `y ∈ spawn.y`, `z ∈ spawn.z`. The x sign is random.
  - `createThreat({ id, type, zone, rng, now = 0 }) → threat` with fields `{ id, type, zone, populated: zone !== 'open' && !THREATS[type].decoy, decoy, p0, p1, p2, t: 0, dur, hitsRemaining: THREATS[type].hits, state: 'inbound', detected: false, alerted: false, engagedBy: null, spawnedAt: now, position: {…p0} }`; `p1 = midpoint(p0, p2) + (0, arc, 0)`; `dur = rngRange(dur[0], dur[1])`.
  - `threatPosition(threat, t, out = {x:0,y:0,z:0}) → out`: quadratic Bézier, plus for `weave` types a horizontal offset perpendicular to the chord `p0→p2` of `sin(t · 4π) · weave`.
  - `threatTangent(threat, t) → {x, y, z}` unit vector of the Bézier derivative (weave ignored).
  - `timeToImpact(threat) → (1 − t) · dur`.
  - `distanceToCity(pos, world = WORLD) → number` (xz distance to `cityCenter`).
  - `isDetectable(threat, detectionRange) → boolean`: true for mortars; else `distanceToCity(threat.position) ≤ detectionRange`.
  - `advanceThreat(threat, dt) → 'inbound' | 'impacted'`: increases `t` by `dt / dur`, clamps to 1, updates `position`; at `t ≥ 1` sets `state = 'impacted'` and returns `'impacted'` (once; a further call on an impacted threat returns `'impacted'` without change).
